# P3.0 — Repository command bar

Owner request (2026-11-09): one bar with the repository's main actions (location, sync, branch, stash,
undo, terminal), in Jit's own style. Today these are spread out: Fetch/Pull/Push are planned as window
toolbar items (Phase 4 §3.4), stash and undo are Phase 8 epics, Open in Terminal is a menu command (⌥⌘T,
Phase 1), and there is no location breadcrumb. This spec gathers them into one bar that grows phase by
phase. **No placeholder buttons:** an action appears only when the phase that implements it ships
(CLAUDE.md "Unbuilt = absent").

## Placement

The window toolbar already holds the tab strip and the profile pill (ADR-0007), and macOS 26 has no second
toolbar row. So the command bar is a **floating Liquid Glass bar at the top of the workbench**, spanning the
graph and inspector panes, directly under the toolbar. It replaces Phase 2's graph-only floating bar: the
branch scope menu and search move to the bar's trailing side. Content (graph, inspector) scrolls under it with
the system scroll-edge effect, and the content inset grows by its height (same mechanism as the Phase 2 bar).
The Phase 4 operation banner (§3.3) stacks directly below it.

```
┌ toolbar: ◧ │ jit ✕ │ other-repo │ + │                                  ⏱ activity · ◉ Work profile ┐
├───────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ jit › ⎇ phase/02-graph… ↑1 ↓0 ▾ │ ◌ 23 changes │ ⟳ Fetch ⤓ Pull▾ ⤒ Push │ ⎇+ Branch │ ⊞ Stash ⊟ Pop │ ↶ ↷ │ >_ │ ⌕ Search  Scope ▾ │
└──────────────── one glass bar; each │ group is one capsule inside a GlassEffectContainer ─────────────────┘
```

## Style (Jit's, not a copy)

- One `GlassEffectContainer`; each action group is a glass capsule (`GlassControlGroup`), separated by
  `Space` tokens, not dividers. No custom blur, no gradients, glass only on the bar (ADR-0006).
- Buttons: SF Symbol over a `type.caption` label in comfortable density; icon-only with tooltips in compact
  density or when the bar is narrower than its labelled width (labels drop first, then whole groups move into
  a trailing `⋯` overflow menu in reverse priority: Terminal, Undo/Redo, Stash, Branch; sync and location never
  overflow). View ▸ Command Bar ▸ Show Labels overrides.
- Disabled actions stay visible but dimmed only when they exist yet can't run now (Pop with no stash, Push
  with nothing to push); the tooltip says why. Actions not yet built are absent.
- Counts use `text.secondary`; ahead/behind as `↑1 ↓0` in monospaced digits. Only failure uses danger colour.
- Motion: progress shows in the Phase 4 activity item, not as spinners in the bar; a running action's
  button shows a small determinate ring (no perpetual animation). Reduce Transparency → opaque surface token.
- Every bar action also exists in a menu with the same title and shortcut (Phase 6 audit rule).

## Behaviour rules

- All actions dispatch through the repository's serialized mutation path (ADR-0027 / Phase 4 OperationCenter)
  and validate against the snapshot they were prepared on. The bar holds no Git state of its own; it observes
  `RepositorySession` (refs, status) — no polling, no timers.
- Destructive paths (force push, discard, undo of a reset) keep their existing explicit confirmation sheets.
- The bar belongs to the active tab; switching tabs swaps its model instantly (no reload).
- Accessibility: the bar is a toolbar-role group; every button has a label and help text; the breadcrumb reads
  "Repository jit, branch phase/02-graph-and-navigation, 1 commit ahead". Full keyboard reach via ⌃F6 focus.

## Tests

- Layout: label drop then overflow order at given widths (unit test on the layout function).
- Location model: branch / detached / unborn / ahead-behind strings from a real `RefSnapshot` (GitTestKit repos).
- Changes count follows status updates; hidden when clean.
- Absent-until-built: a test asserts the Phase 3 bar exposes exactly Location, Changes, Terminal, Search/Scope.
- Light/dark and Reduce Transparency screenshots; narrow-window screenshot with overflow.
