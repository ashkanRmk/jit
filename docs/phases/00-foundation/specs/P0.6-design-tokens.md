# P0.6 — Design direction and tokens v1

## Behavior
- `DesignSystem` defines content tokens as data (`ColorSpec` with light / dark / light-HC / dark-HC),
  resolved through dynamic `NSColor(name:dynamicProvider:)`; type, spacing, radii, borders, shadows,
  motion, icon sizes, panel metrics, density.
- Glass helpers encode the usage rules: `jitGlass(in:)` (the only `glassEffect` call, with an opaque
  `surface.chromeOpaque` fallback under Reduce Transparency), `GlassControlGroup`
  (`GlassEffectContainer`), `FloatingGlassCapsule`, `primaryGlassButton()` (`.glassProminent` +
  `accent.tint`), `secondaryGlassButton()` (`.glass`). Content helpers: `contentCard()`,
  `RowBackground`, `focusRing`, `Selection`.
- Accent decision: selection and focus follow the **system accent** (`Selection`); Tidewater remains the
  tint of the primary glass action. Reason: in renders, Tidewater at 12 % on `surface.panel` read as
  grey; the system accent reads as selection and matches other Mac apps.
- Debug-only gallery window (Debug ▸ Design System, ⌥⌘D).

## Tests (`swift test`)
Contrast per variant (light, dark, both Increase Contrast): primary/secondary text ≥ 4.5:1 on every
content surface; tertiary text, accent, status and diff marks ≥ 3:1; lanes ≥ 3:1 on canvas; text on
diff backgrounds and on accent ≥ 4.5:1; Increase Contrast variants strictly stronger; WCAG math
reference values. Appearance resolution (incl. Increase Contrast), dynamic color resolution, opaque
Reduce Transparency fallback. Lint: no hardcoded colors/fonts/blur/glass outside `DesignSystem`.
Draft value changed by the contrast test: `text.tertiary` light `#878C92` → `#7A7F85` (2.87:1 → 3.42:1
on `surface.sunken`).
