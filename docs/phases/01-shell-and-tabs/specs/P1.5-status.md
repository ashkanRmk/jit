# P1.5 — `GitCore` status and operation state

## Behavior
- Command: `git --no-pager -c core.quotepath=false -c color.ui=false --no-optional-locks status
  --porcelain=v2 -z --branch --untracked-files=normal` with `GIT_OPTIONAL_LOCKS=0` (read kind), 120 s
  timeout, 128 MiB output cap. All flags exist in Git 2.39 (minimum).
- `StatusParser` works on the raw bytes (`memchr` for NULs; no `String` per record). Records: `#` headers
  (`branch.oid` incl. `(initial)`, `branch.head` incl. `(detached)`, `branch.upstream`, `branch.ab`;
  unknown headers ignored), `1`, `2` (+ NUL-separated original path), `u`, `?`, `!`. Paths may contain
  spaces, newlines and any Unicode. Malformed/truncated input → `GitCoreError.internalError`.
- `StatusEntries`: Git's output buffer + parallel arrays (kind, packed XY, submodule flags, metadata range,
  path range, original-path range); strings materialized on demand. `StatusSummary`: a partially staged
  file counts as staged and unstaged; unmerged entries count only as conflicted.
- `OperationStateDetector.detect(gitDirectory:)` reads the per-worktree git dir: `rebase-merge/`
  (`msgnum`/`end`), `rebase-apply/` (`applying` → applying mailbox, else `next`/`last`), `MERGE_HEAD`,
  `CHERRY_PICK_HEAD`, `REVERT_HEAD`, `BISECT_LOG`.
- `actor RepositoryHandle` (from `GitEngine.openRepository(at:)`): generation counter; `status()` returns
  the cache when current, otherwise shares one in-flight computation; a computation that finished at an
  older generation is discarded and the next one shared; caller cancellation cancels the computation
  (killing Git's process group); `invalidate(_:)`, `releaseCaches()`, `lastSnapshot()` (Phase 3). Bare
  repositories: HEAD + operation state only (no working tree).
- `GitEngine.readGlobalIdentity()`: `git config --global --get user.name|user.email`, read-only.
- Discovery now reports `pathNotFound` for a missing folder (was a launch failure).
