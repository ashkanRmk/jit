# P1.6 — File watching

## Behavior (ADR-0008)
- `RepositoryWatcher`: one `FSEventStream` per *active* session, `kFSEventStreamCreateFlagUseCFTypes |
  WatchRoot` (directory-level, no per-file events), latency 0.2 s, delivered on a private serial queue.
  Roots: the worktree, plus git/common directories outside it (linked worktrees, separate git dir); bare:
  the git dir. Paths are canonicalized (`realpath`) to match what FSEvents reports.
- `FSEventClassifier.classify(path:flags:layout:)` (pure): `objects/`, `logs/`, `hooks/`, `*.lock`,
  `FETCH_HEAD`, `ORIG_HEAD`… → ignore; `index` → index; `HEAD` → head; `refs/`, `packed-refs` → refs;
  `config` → config; `MERGE_HEAD`, `rebase-*`, `sequencer`, … → operationState; `info/`, `modules/` →
  worktree; other worktrees' private dirs → ignore; the git dir itself (directory-level event for a file
  directly inside it) → index+head+refs+config+operationState; worktree paths → worktree;
  `MustScanSubDirs`/dropped → everything; `RootChanged` → root check (missing → `pathNotFound` error).
- Per batch: union of kinds → `handle.invalidate` → one refresh; one refresh in flight plus one queued.
- Lifecycle: the stream runs only while the tab is visible, the app active, and the window neither
  miniaturized nor occluded (`NSWindow.occlusionState`); otherwise it is stopped. Returning to the
  foreground triggers exactly one revalidation. `core.fsmonitor` is left to Git.
