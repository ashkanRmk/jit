# P1.8 — Identity-only profiles

## Model
- `GitIdentity { name, email }` (`GitCore`, `Codable`). `GitProfile { id, displayName, colorIndex, author,
  committer? }` (`Services`). `profiles.json = { version, profiles, activeProfileID }`, `0600`. No secret
  fields exist (test asserts the exact key set); Phase 5 adds only Keychain references.
- `ProfileSnapshot { profileID, author, committer (= committer ?? author) }` — an immutable value captured
  when an operation starts; Phase 3 applies it through `GIT_AUTHOR_*`/`GIT_COMMITTER_*` for one invocation.
- Rules: the first profile created becomes active; deleting the active profile leaves *none* active (never
  auto-selects another); `setActive` ignores unknown ids.

## Validation
Errors (block saving): empty display name, empty name/email, `<`, `>` or line breaks in names, spaces/`<`/`>`
in emails. Warning (allowed): an email without exactly one `@` and a dot inside the domain.

## UI
- Toolbar capsule: avatar (8 profile swatches — neighbors of the lane palette, never lane colors) +
  display name (hidden below 1100 pt window width). The toolbar item's system platter provides the glass;
  no profile → "No Profile" with the item's system `.prominent` style tinted `status.warning`.
- Switcher: system `NSPopover` (system glass), rows avatar / name / `name <email>` / checkmark, search
  above 6 profiles, New Profile… / Manage Profiles…; empty state "Commits need an identity" with Create
  Profile… / Fill from Git config.
- Editor: system sheet, grouped form, color swatches, collapsible committer override, inline issues,
  "Fill from Git config" (read-only `git config --global --get`), "Jit never changes your global Git
  configuration."
- Settings ▸ Profiles: list, add, edit (double-click), Make Active, delete with a confirmation that says
  whether it is the active profile.
