# P1.1 — App state architecture and persistence

## Behavior
- `Services` (new target, imports `GitCore`, no UI): `StoreLocation` (`~/Library/Application Support/Jit`,
  `0700`; `JIT_APP_SUPPORT=<dir>` overrides it for tests, screenshots and benchmarks), `JSONFile`
  (versioned load; unknown version or undecodable file → moved to `<name>.bak-<yyyyMMdd-HHmmss>` and reset;
  atomic write = new `0600` temp file in the same directory + `fsync` + `rename`), `DebouncedWriter` (one
  cancellable one-shot `Task`, 500 ms after the last change; never a repeating timer; `flush()` writes
  synchronously at quit), `SessionStore` (`session.json`), `RecentsStore` (`recents.json`),
  `PreferencesStore` (`UserDefaults`: appearance, restore tabs), `ProfileStore` (`profiles.json`, P1.8).
- `session.json`: `{version, windowFrame, layout{sidebarWidth, inspectorWidth}, tabs[{id, kind, path,
  titleCache, branchCache, sidebarCollapsed, inspectorCollapsed, ui}], activeTabID}`. `ui` is arbitrary
  JSON per feature (`JSONValue`), stored and round-tripped without interpretation.
- `Features/App`: `AppModel` (ordered `TabModel`s, `activeTabID`, in-memory reopen stack of 10, stores,
  foreground flag), `TabModel` (`@Observable`: title, branch, status dot — the only fields the tab strip
  observes), `LayoutState` (global widths clamped to `PanelMetrics`).
- `RepositorySession` lifecycle `unloaded → loading → active ⇄ inactive → suspended`, `closed`. Restored
  tabs stay `unloaded` (no handle, no watcher) until shown. Deactivation stops watching and cancels work.
- `MemoryPressureMonitor`: `DispatchSource.makeMemoryPressureSource(.warning/.critical)` → inactive
  sessions `suspend()` (handle caches released) and their cached tab controllers are dropped.

## Failure cases
Corrupt/partial or future-version files are backed up, never silently overwritten. A failed write leaves
the old file and no temporary file. A missing Application Support directory is created with `0700`.
