# P6.1 — Signposts and measurement plumbing

## Behavior
- One registry, `GitCore/Diagnostics/Signposts.swift` (GitCore so core spans and app intervals share it;
  Services/Features/App import GitCore). Subsystem `com.example.jit` (the bundle identifier placeholder).
- Intervals (name = `<category>.<what>`): `launch.firstWindow`, `repo.open`, `graph.firstPage`, `graph.page`,
  `diff.switch`, `tab.switch`, `ops.run`; GitCore: `core.historyPage`, `core.laneLayout` (parse + layout of one
  read chunk), `core.status` (parse), `core.diffParse`, `core.patchBuild`, `core.git` (subprocess spawn → exit).
- All intervals use the **Points of Interest** category: `xctrace record` only enables dynamic tracing for
  Points of Interest, so custom categories were silently dropped from scripted traces (found in the xctrace
  spike). The category is the name prefix instead.
- Details are counts or the Git subcommand (`Signposts.gitSubcommand`, a lowercase word or "git") — never
  paths, refs, URLs, titles or arguments. `ops.run` carries no detail (titles contain branch names).
- Zero-cost rule: `OSSignposter` is near free while no trace records; the test hook is one unfair-lock read.
- End points: `launch.firstWindow` ends one main-queue turn after the first window becomes key;
  `repo.open` and `graph.firstPage` end when the first graph rows are on screen; `diff.switch` ends after the
  view displays the new source; `tab.switch` ends one main-queue turn after selection (layout + display).
- `-JitBenchmarkScenario <name>` (all builds, inert unless passed): scripted, read-only scenarios against
  local repositories from `JIT_BENCH_REPOS`/`JIT_OPEN`; unknown names report `error=unknown-scenario` and run
  nothing. Measurements come from the same intervals (a recorder installed through the test hook).

## Failure cases
- Unknown scenario / no repository → one error line, no action. Relative or `//host` paths are ignored.
- Ending a token twice is a no-op (observed); an interval whose work is cancelled still ends.

## Tests
- `SignpostNamingTests`: unique, prefixed names; design list present; begin/end paired; double end ignored;
  a real status refresh emits paired `core.status` and `core.git`; `gitSubcommand` never returns arguments.
- `BenchmarkScenarioArgumentTests`: absent → inert; every scenario parses; unknown/missing name; local
  absolute paths only (caught a real hole: `https://…` split on `:` left `//host/…`); percentile math.
- Verification: `scripts/benchmarks/instruments/trace.sh` records a Release launch + open and extracts every
  interval headlessly.
