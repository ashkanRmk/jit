# P6.9 — Command palette and keyboard workflows

## Behavior
- ⌘K (View ▸ Command Palette…) toggles a borderless child panel of the main window: one glass container,
  top edge anchored ~18 % below the window top; the panel is key (field focused) but never main.
- Sources (local only): registry commands with menu path and shortcut; branches (local/remote) and tags of the
  visible tab; changed files, then tracked files (`git ls-files`, lazy, ≤ 100,000, per repository revision,
  2 repositories cached); open tabs then recents; SHA prefix (`:` or ≥ 7 hex) among loaded commits.
- Prefix scopes `>` `@` `/` `#` `:` (key chips in the field). Empty query: last 5 commands run from the palette,
  then enabled commands ordered repository → branch → view → edit → file → window → help → app.
- ↑/↓ move (announced to VoiceOver), ↩ primary, ⌘↩ secondary (branch: Check Out through the operations flow;
  file: File History / Reveal; tab/recent: Reveal in Finder), ⎋ or ⌘K closes; clicking outside closes.
- Disabled commands are listed muted with their reason and never run (beep).
- Keyboard: ⌥⌘← / ⌥⌘→ move focus between sidebar, main pane and inspector; ⌘+ / ⌘- / ⌘0 code text size.

## Failure cases
- File index fails → one "Files unavailable — <reason>" row; other sources keep working.
- No matches → "No matches for "…"" with the prefix hint.

## Tests
- `FuzzyRankerTests` (subsequence, word starts incl. camel case, consecutive runs, prefix, recency, ties,
  scopes, keyword weight, cap 50); `CommandRegistryTests` (menu = registry parity, unique ids, no shortcut
  conflicts, standard shortcuts untouched, glyphs, palette visibility); `SnapshotTests.commandPalette`.
- Real app, real keystrokes: ⌘K → `@inspector-2006` → ↩ selects the branch tip; ⎋ closes; ⌘K toggles; panel top
  fixed while results resize.
- Not built: XCUITest targets (`PaletteNavigateToBranchUITest`, keyboard-only commit and conflict flows) — the
  project has no UI-test target; the flows were driven with System Events keystrokes instead (carry-over).
