# P2.2 — Refs model

## Behavior
- `RepositoryHandle.refs()` → `RefSnapshot`: one `git for-each-ref --format=…` call (fields NUL-separated,
  records newline-terminated — ref names cannot contain control characters) run concurrently with HEAD
  resolution (`symbolic-ref` + `rev-parse --verify HEAD^{commit}`).
- Each `GitRef`: full name, kind (local/remote/tag/other), object id, peeled commit (`%(*objectname)` when
  the ref is an annotated tag; `nil` for refs to trees/blobs → "non-commit tag" in the navigator),
  upstream short name, ahead/behind from `%(upstream:track,nobracket)`, `upstreamGone`, `isHead`.
- Symbolic refs (`refs/remotes/origin/HEAD`) are excluded from `refs` and kept in `remoteHeads`.
- `ObjectID`: inline 32-byte value (4 × UInt64), SHA-1 uses the first 20 bytes; object format read once
  per handle with `rev-parse --show-object-format`.
- `revision`: FNV-1a over Git's raw output + HEAD (`StableHash`, stable across launches).
- Parsing is byte-level; `String`s only for ref names/upstreams (refs are few relative to commits).

## Failure cases
Malformed record/object id → `internalError` with a user-presentable summary; Git failures classified like
discovery (not a repository, permission, dubious ownership).

## Tests (`RefsTests`)
`objectIDRoundTrip`, `refsParseBranchesRemotesTags`, `refsAnnotatedTagPeeled`, `refsTagToBlobHasNoCommit`,
`refsParseDetachedHead`, `refsParseUnborn`, `refsUpstreamTrackingAndGone` (ahead 2 / behind 1, `[gone]`),
`refsUnicodeBranchNames`, `refsRevisionChangesWithRefs`, `parseTrackVariants`, `refs10kBranchesUnder100ms`.

## Result
10k refs parse: 4 ms release (`swift test -c release -Xswiftc -enable-testing --filter refs10k`), 190 ms debug.
