# P2.1 — Fixtures & benchmark repositories

## Behavior
- `GitTestKit.Topology`: a value describing a commit graph with labelled commits — `commit`, `linear(n)`,
  `branch(name, from:)`, `checkout`, `merge(…, label:)` (any number of parents → octopus), `orphan`,
  `tag` (lightweight or annotated), `ref` (arbitrary full ref name, e.g. remotes), `detach(at:)`.
  `write(to: TestRepo)` imports it with `git fast-import`, points HEAD (symbolic or detached), checks
  out the tree, and returns label → object id. Fixed identity and dates (+60 s per commit) → stable oids.
  A crisscross is two `merge` calls on two branches.
- `GitTestKit.SyntheticHistory`: large fixtures (see `docs/performance.md` → Methods → History fixtures);
  SplitMix64 with a fixed seed, so output is reproducible byte for byte.
- `JitBench make-history <commits> <branches> <out>` and `scripts/benchmarks/make-history-fixture.sh`
  (`--standard` = 1k / 10k / 100k under `~/Library/Caches/jit-bench/`).
- fast-import is run through Foundation `Process` in GitTestKit only (needs stdin); `GitCore` keeps its
  stdin-less runner.

## Tests
`TopologyTests`: `testkitTopologiesAreDeterministic` (two sandboxes → identical label→oid maps),
`topologyShapesMatchGit` (octopus parents, orphan root, annotated tag, remote ref, clean worktree),
`detachedHead`, `syntheticHistoryIsReproducible` (1k built twice → same HEAD).

## Result
100k fixture builds in 6.2 s (target < 60 s); HEAD `f7f2678…` on every build.
