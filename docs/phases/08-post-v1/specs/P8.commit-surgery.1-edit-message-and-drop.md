# P8 — Direct Edit Message and Drop Commit

## Scope
- Add single-commit graph menu actions **Edit Message…** and **Drop Commit…**.
- Edit Message opens a focused multiline message sheet seeded with the complete original message.
  Review shows the exact action/commit, affected descendants, publication warning and old branch tip.
  Drop opens that confirmation directly. Cancel and the default Return action never mutate Git.
- Older message edits and drops generate a validated plan over the existing interactive rebase engine.
  HEAD message edits use a message-only amend, preserving its tree, parents and original author.
  Root/merge HEAD messages can be amended; root/merge drops and older ranges containing merges are
  refused. Other branches/tags stay in place. This slice does not add squash, fixup, move or split actions.

## Safety and lifecycle
- Require a working tree, attached branch, no operation in progress and clean tracked index/worktree.
  Untracked files are retained. Selected commits must belong to the current branch's supported range.
- Immutable plan provenance binds the originating worktree git directory and captures HEAD/refs/operation. A changed repository at execution is refused;
  editing a message after confirming invalidates the confirmation token. Message bounds: nonempty,
  no NUL, at most 1 MB; literal Unicode, quotes, shell characters and comment lines remain literal.
- Both actions require explicit action-specific ConfirmationToken authorization. Show known
  remote-tracking reachability, rewritten commit count and reflog recovery SHA before confirmation.
- Serialize mutations through the existing writer, retain hooks, capture the active profile as
  committer on confirmation, and reuse operation progress, resolver, Continue/Skip/Abort and recovery
  journal. Avoid opening the general rebase editor for these direct actions.
- Async preparation must not replace a newer sheet or open on a closed session. Native controls use
  DesignSystem tokens and standard sheet/menu conventions.

## Verification
- Real repositories: older/HEAD/root/merge-HEAD reword, middle/HEAD drop, literal messages, retained
  trees/parents/authors/unrelated refs, published warnings, stale/dirty/detached/off-branch refusals,
  token mismatch, hook refusal, drop conflict/abort, and reflog recovery of a dropped commit.
- Controller/menu tests cover preparation, cancellation, edited payloads and execution/error routing.
- Build, appropriate package/app regressions, light/dark captures and native graph-menu acceptance
  for Edit Message and Drop Commit, including cancel-before-confirm and resulting Git history.
