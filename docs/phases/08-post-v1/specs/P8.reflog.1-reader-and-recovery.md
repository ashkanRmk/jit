# Reflog reader and recovery points

Status: implemented locally, 2026-11-18. Requirements: §9.2, §13.5, §16, §19.

- Read HEAD or an exact local branch's reflog in pages of at most 50. Parse NUL-delimited bytes;
  classify actions and use the reflog event time, not the commit's committer time.
- A cursor identifies the ref, reflog file stamp and repository state. Reject changed cursors instead
  of skipping or duplicating entries after concurrent writes or expiration.
- Mark reachability on demand for the page only, including detached HEAD ancestry. No background scans.
- Find Lost Commits explicitly runs cancellable `fsck --unreachable --no-reflogs --no-lost-found`;
  report progress, bound output/results, identify possible stash commits and never write recovery refs.
- Capture previous HEAD, changed/deleted refs and removed older stashes inside the existing writer gate, including partially
  successful operations. Keep 50 points per handle. Persist a bounded journal outside the repository;
  earlier sessions' points are informative, never silently eligible for Undo.
- Recovery targets are immutable full OIDs. Create branch uses the existing writer and state token;
  cherry-pick and reset use existing sheets and confirmation. Never resolve a moving numeric selector
  at execution time. Never claim discarded working-tree changes can be recovered.

Tests: real repositories covering amend/reset/checkout classifications, event timestamps, pagination,
stale cursor refusal, unborn/disabled reflogs, SHA-256, detached HEAD, dropped stash discovery,
cancellation with process-group cleanup, safety fingerprints and journal bounds.

The planned ADR-0050 number is occupied by Gravatar; recovery uses ADR-0052.
