# Reset preview and execution

Status: included in 0.0.8, 2026-11-18. Requirements: §9.2, §13.5, §16; ADR-0015/0027/0052.

- Typed soft/mixed/keep/hard modes retain Git semantics. Preview is read-only and names the exact target,
  previous HEAD, staged/unstaged files, and commits that will lose reachability from HEAD/all refs.
  Other branches/tags keep commits reachable; display the count and first five subjects.
- Confirmation binds the preview ID, mode, target and stash choice. Revalidate the repository root, refs, operation state,
  index, status and fingerprints of changed files inside the existing writer before any mutation.
- Hard reset lists tracked changes that will be discarded. Ordinary untracked files remain intact.
  Refuse untracked/ignored/directory obstructions rather than let Git overwrite them, including when
  stash-first is selected. Users can move/stash those paths separately, then refresh the preview.
- Stash first is default-on for dirty hard resets, explicitly includes untracked files, uses the active
  identity snapshot and runs stash plus reset in one writer job. Failures before stash change nothing;
  a stash failure prevents reset. If stash succeeded but reset fails, preserve the stash and report its
  exact SHA; never claim the whole operation rolled back or automatically pop it.
- Once the stash/reset chain starts it is not interruptible by caller cancellation. Check the state
  again after stash; reject unexpected refs/HEAD or remaining local changes. No automatic stash restore.
- Refuse in-progress operations/unmerged files and hard/keep with hidden index flags (skip-worktree or
  assume-unchanged), or stash-first with dirty submodules. Never recurse into submodules. Refuse an
  unborn HEAD with guidance rather than guessing a recovery state.
- Reuse recovery points and the stash manager. Show the previous HEAD and retained stash SHA in the
  result, with clear guidance for recovering committed history and applying the saved stash.

Tests: real repositories and fingerprints for mode semantics, keep conflict refusal, exact loss lists,
shared/remote reachability, changed index/worktree/untracked files, stale refs, wrong confirmation,
untracked/ignored obstructions, sparse/hidden flags, rename/binary/symlink paths, stash identity/content,
stash failure/reset failure, one writer job, cancellation and recovery through a branch plus stash.
