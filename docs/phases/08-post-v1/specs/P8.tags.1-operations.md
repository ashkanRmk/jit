# Tag management operations

Status: implemented locally/unreleased, 2026-11-18. Requirements: §9.2, §13.5, §16; ADR-0015/0027/0052/0062.

- Extend the existing create/validate/push implementation. Validate exact `refs/tags/<name>` with Git;
  reject duplicate/invalid names, stale repository state, invalid commit targets and empty annotations.
  Lightweight tags need no profile. Annotations use the captured profile identity, a 0700 temporary
  directory and 0600 message file, removed on success/failure/cancellation. Never put messages in argv.
- Read exact tag objects on demand: lightweight/annotated kind, direct object ID, fully peeled target,
  object type, tagger identity, date and annotation. No signature-verification claim. Bound output size.
- Local deletion requires a token naming the tag and exact direct object OID; revalidate state and use
  compare-and-delete `update-ref --no-deref`. Preserve HEAD/index/worktree and record the exact tag
  object in the existing recovery journal; return the direct object and peeled target.
- Push exactly the selected tag object to an explicitly chosen configured remote. No force, implicit
  follow-tags/mirror, branch pushes or recursive submodule push. A different remote tag is rejected.
- Remote deletion first reads the exact tag at the effective push destination (not the fetch URL), then
  confirms its immutable OID, remote, destination and repository. Revalidate local state/config inside
  the writer and delete only under an explicit object lease. Keep the local tag. Refuse multiple push
  destinations and embedded URL credentials; refuse URL rewrites that would reroute the prepared URL.
  Every network command uses GitEnvironment and profile access. Failures never pretend local rollback.
- Real-repository tests cover names, identity/message permissions and cleanup, old commits, annotation
  metadata, lightweight/blob/nested/SHA-256 tags, duplicate/stale/wrong-token/CAS safety, local recovery,
  one-tag push despite follow-tags/mirror config, remote rejection/change, separate fetch/push URLs,
  missing tag, changed destination, multiple destinations and remote-hook refusal.
