# P8.accounts.1 — Account tabs and one-step Connect

Requirements: §10, §12, §26 (priority 1). Builds on ADR-0016, ADR-0017, ADR-0035.

## Why
Connecting an account took a sheet with a provider picker, a method switch, Validate, then Save; a
self-managed GitLab server had to be added in Servers & Network first; GitHub Enterprise Server could not be
connected at all.

## Behaviour
Settings ▸ Accounts has four tabs (`AccountTab`): GitHub, GitHub Enterprise, GitLab, GitLab Self-Managed.

- **Not connected** — the tab shows the connect form:
  - GitHub Enterprise and GitLab Self-Managed: **Host Domain** and **Personal Access Token**, then Connect.
  - GitHub and GitLab: **Personal Access Token**, then Connect. When the build's `OAuthClients.plist` has a
    client ID for that service, a **Connect with GitHub / GitLab** button appears above it and runs the
    existing ADR-0017 flow (GitHub device code, GitLab authorization code + PKCE). Without a client ID the
    button is absent, never disabled or faked.
- **Connect is one step** (`AccountsService.connect(tab:host:token:)`): `GET /user` plus token info; only an
  accepted token is stored in the Keychain and recorded. A 401, a transport failure or a Keychain refusal
  saves nothing — no account and no server.
- **Host Domain** (`HostDomain.webBaseURL`): `git.corp.example`, `git.corp.example:8443/gitlab` or a full
  `https://…` URL. Refused: `http://` and other schemes, credentials, query, fragment, whitespace, hosts that
  are not plain hostnames. `github.com` / `gitlab.com` typed into the matching self-hosted tab resolve to the
  built-in server.
- **Server record** — a new host becomes a `ProviderInstance` named after the host (SSH host = same host,
  port 22, proxy "Same as global"). An existing server with the same kind, host, port and path is reused.
  CA certificates, proxy, SSH port and the GitLab OAuth application ID stay editable in Servers & Network,
  which now lists GitHub Enterprise servers too and keeps their kind on save.
- **Same user again** — connecting a user who already has an account on that server replaces that account's
  token instead of adding a second record.
- **Connected** — the tab lists its accounts per server: name, login, status ("Connected"), method, scopes,
  expiry, last check, Check Now, Replace Token… / Reconnect…, Disconnect… (unchanged destructive sheet).
  "Add Another Account…" shows the form again.
- GitHub Enterprise uses `https://<host>/api/v3` and is token-only (a browser flow would need an OAuth app
  registered on each server).

## Enabling one-click sign-in
`macos/App/Resources/OAuthClients.plist` ships with empty values. Fill `GitHubClientID` (OAuth App with
"Enable Device Flow") and `GitLabClientID` (non-confidential application, redirect `jit://oauth/gitlab`,
scopes `read_api read_repository write_repository`). Client IDs only — never a secret.

## Not in scope
Generating an SSH key and uploading it to the server; profile pictures on the account row.

## Tests
`AccountConnectTests` (stub transport, in-memory secret store): host parsing, one-step connect creating the
server, GitHub Enterprise `/api/v3`, rejected token saves nothing, invalid input never reaches the network,
reconnecting reuses server and account, SaaS tabs use built-in servers, replace requires the same user.
