# P7.1–P7.2 Release configuration and architectures

**Behaviour.** One file, `macos/App/Config/Version.xcconfig`, defines the bundle ID, version, build and copyright.
Xcode reads it through `Base.xcconfig`; the release scripts read it through `lib.sh`. A Release archive is
stripped (dead code, symbols) with dSYMs kept separately. Architectures come from `JIT_ARCHS`
(`release.env`): arm64 for 1.0.0 (ADR-0049).

**Failure cases.** `--version` that differs from the xcconfig → the script stops. A built Info.plist that
disagrees with the xcconfig → `01` stops. Any Mach-O with other slices, a missing helper or Git, or
dev-only content (TestRig, JitBench, GitTestKit, xctest, swiftmodule, dSYM, keys, .DS_Store) → `03` stops.

**Checks.** `01-build-app.sh` (plist assertions, helper present), `03-verify-archs.sh`; `09-validate.sh`
repeats the architecture check on the app inside the DMG.
