# P7.7–P7.9 Signing, DMG, notarization, validation

**Steps** (`scripts/release/`, each idempotent and runnable alone, output in `build/release/<version>/`):
01 build → 02 bundle Git → 03 verify architectures and contents → 04 sign nested code inside-out → 05 sign the app
and verify → 06 DMG → 07 notarize → 08 staple → 09 validate. `release.sh [--version] [--adhoc]
[--skip-notarize] [--from-step N]` runs them and prints a summary (artifact, SHA-256, identity, notary
ID/status, staple, validation result).

**Failure cases.** Unsigned app before 06 → stop. Ad-hoc build at 07/08 → refused with the exact
configuration needed. Missing notary profile → the `store-credentials` command to run. Notary rejection →
the log is fetched and its issues printed, then stop. Finder layout not written → stop, with the hint to
allow Automation or set `JIT_DMG_LAYOUT=0`. Any validation row not matching its expectation → stop;
`validation.txt` holds the evidence.

**Secrets.** None pass through the scripts: the identity is a keychain name and notarization uses a notarytool
keychain profile. `release.local.env` and signing files are git-ignored.
