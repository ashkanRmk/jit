# P4.7 — Clone from URL

## Behavior
- `CloneURL.classify`: https, ssh/git+ssh, scp-like, git, local path / file; `http://` only with an explicit
  insecure-transport confirmation; `-…`, `transport::address` (ext, fd, …) and unknown schemes refused.
- Destination: parent must exist; folder must not exist or be empty; name derived from the URL, editable.
- `git clone --progress -- <url> <dest>` with the remote environment; cancel or failure removes the folder
  if Jit's request created it, or empties a pre-existing empty folder (never removes it).
- `.gitmodules` present → outcome says submodules were not cloned (Phase 8).

## Tests
`cloneFileURLSucceeds`, `cloneRejectsDashPrefixedURL`, `cloneRejectsExtProtocol`,
`cloneInsecureHTTPRequiresConfirmation`, `cloneCancelRemovesCreatedDestination`,
`cloneCancelPreservesPreexistingEmptyFolder`, `cloneIntoNonemptyFolderBlocked`,
`cloneAuthRequiredFailsFastNonInteractive` (local HTTP 401 stub).
