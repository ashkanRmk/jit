# P4.6 — Push

## Behavior
- `push --progress --porcelain [--set-upstream] <remote> refs/heads/<local>:refs/heads/<remote>`; porcelain
  lines parsed per ref (` `, `+`, `*`, `-`, `=`, `!`), rejection classified: non-fast-forward / fetch first,
  stale info (lease), remote rejected (hook, with sanitized `remote:` lines), other.
- Force push only as `forcePushWithLease(expected:token:)` → `--force-with-lease=<ref>:<oid>
  --force-if-includes`; the token must name the same remote, ref and expected OID. Plain `--force` never
  appears in the source (test).
- Cancel: the remote may already have the commits; Jit runs `ls-remote` (uncancellable) and reports the
  actual result.

## Tests
`pushFastForward`, `pushPublishesAndSetsUpstream`, `pushRejectedNonFFClassified`,
`pushRejectedByHookShowsRemoteLines`, `forceWithLeaseSucceedsWhenExpectedMatches`,
`forceWithLeaseFailsWhenRemoteMoved` (remote unchanged), `forcePushNeverUsesPlainForce`,
`pushCancelReportsActualRemoteState`.
