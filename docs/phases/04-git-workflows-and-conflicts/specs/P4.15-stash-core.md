# P4.15 — Stash core

## Behavior
- `stashes()`: `stash list -z --format=%gd%x00%H%x00%P%x00%ct%x00%gs` (5 NUL fields; messages may contain
  newlines/Unicode); branch and message derived from the reflog subject.
- `stashPush` (`-m`, `--include-untracked`, `--keep-index`, `--staged`, literal pathspecs on stdin) with the
  profile identity; nothing to stash → refused.
- `applyStash(index, oid, pop)` / `dropStash(index, oid, token)` validate `stash@{n}` still names `oid`
  (indices shift); pop with conflicts keeps the stash; `clearStashes(token)`.
- `stashAndSwitch`: stash (with untracked) → switch in one gate hold; if the switch fails the stash is popped
  back and the error says so.

## Tests
`StashTests`: list parsing, include-untracked round trip, keep-index bytes, staged-only, path subset, nothing to
stash, pop conflict keeps stash, shifted index refused, untracked collision, clear, stash-and-switch success
and `stashAndSwitchRestoresStashWhenSwitchFails` (fingerprint of working tree and HEAD).
