# P4.4 — Fetch, ahead/behind, remotes inspector

Design: §3.4, §4.6.

## Behavior
- `fetch(FetchRequest{remote|all, prune})`: remote must be one of `git remote`; `--prune`/`--no-prune` always
  explicit; progress streamed; cancellable any time — Git updates refs at the end, Jit re-reads refs
  (uncancellable read) and reports how many changed. Symbolic refs (`origin/HEAD`) are not counted.
- Ahead/behind and `[gone]` come from Phase 2's `for-each-ref` ref snapshot (no network).
- `remotes()`: names, fetch/push URLs, refspecs, effective prune (`remote.<n>.prune` → `fetch.prune`).
  `RemoteInfo.masked` hides `user:password@` and token-shaped strings and flags them.

## Tests
`fetchUpdatesRemoteRefs`, `fetchPruneExplicit`, `fetchRejectsUnknownRemote`, `fetchCancelLeavesRefsConsistent`
(10 MB random pack via local bare remote; refs old or new; `fsck --connectivity-only` clean),
`aheadBehindCounts`, `upstreamGoneDetected`, `remoteURLUserinfoMasked`.
