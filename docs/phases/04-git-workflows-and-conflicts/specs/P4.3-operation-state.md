# P4.3 — Operation-state detection and banner

Design: §3.3, §4.9.

## Behavior
- `RepositoryHandle.operationState()` → `RepoOperationState` read from the per-worktree git directory
  (`rev-parse --git-dir` already points at `.git/worktrees/<n>` in linked worktrees): `rebase-merge/`
  (head-name, onto, msgnum, end, stopped-sha), `rebase-apply/` (`applying` → am), `MERGE_HEAD` (+ `MERGE_MSG`
  for the source), `CHERRY_PICK_HEAD`, `REVERT_HEAD`, `sequencer/todo`, `BISECT_LOG`. Conflict count from
  `ls-files -u`.
- The banner refreshes from FSEvents invalidation of the git dir (Phase 1 watcher) and after every operation.
- am / bisect are informational ("Finish it in Terminal").

## Tests
`StateDetectionTests`: merge, rebase (merge + apply backends), am, cherry-pick, revert, sequencer, bisect,
linked worktree — every state created by Git itself, as if from Terminal.
