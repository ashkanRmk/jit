# P4.2 — Activity UI, confirmation sheet, error presentation

## Behavior
- `OperationCenter` per repository session (`session.operations`): records newest first, running + last 20
  finished, in memory only; states running / succeeded / failed(PresentableError) / cancelled / needs attention;
  "Waiting for “X”…" when another operation holds the write gate; cancel only for cancellable kinds (fetch,
  pull's fetch phase, clone, push with warning).
- Activity toolbar item: a standard `NSToolbarItem` (system glass), inserted only while the active tab has
  activity (no reserved empty chrome); running = small ring (determinate with Git %) + label; finish = one-shot
  checkmark (160 ms in, ~900 ms hold, 200 ms out); otherwise a quiet clock glyph. Popover lists operations with
  outcome, duration, Cancel, and a Details disclosure for failures. Repository ▸ Show Activity (⌥⌘A).
- `ConfirmationSheet` (system sheet): title naming action + object, context line, what changes, what may be
  lost, recoverability with a copyable SHA; Cancel is default (Return/Esc); the destructive button repeats the
  verb, has no shortcut, and for force push / remote delete enables only after 600 ms.
- `PresentableError` maps every `FailureKind` to a title, explanation and recovery actions; a changed SSH host
  key never offers Retry; cancellation is neutral and never shown as an error sheet.

## Deviation
- Phase 3's DiscardSheet keeps its own layout (preview of lost lines) — same rules (Cancel default, no shortcut
  on Discard); not rebuilt on ConfirmationSheet.
