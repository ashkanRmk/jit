# P4.8 — Branch operations and Phase 2 write actions

## Behavior
- Names validated by running `git check-ref-format --branch` (and "already exists" check).
- Create (`branch --no-track` / `switch --no-track -c`), switch (`switch --no-guess`), check out remote
  (`switch -c <local> --track refs/remotes/<r>/<b>`), detach (`switch --detach <oid>`), rename (`branch -m`,
  upstream follows, remote not renamed), delete (`-d`; `branchNotFullyMerged` → second sheet listing unmerged
  commits → `-D`; both need tokens), delete remote (`push --delete`, high-risk token), set/unset upstream.
- Switch blocked by a dirty tree is an outcome (`wouldOverwrite(paths:untracked:)`) and changes nothing; the
  sheet offers Cancel / Stash and Switch. "Discard These Changes…" was dropped (design §7 review): Stash and
  Switch covers the need without data loss.
- All take a `RepoStateToken`; a stale token changes nothing.
