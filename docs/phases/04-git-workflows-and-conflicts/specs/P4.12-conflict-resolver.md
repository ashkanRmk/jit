# P4.12 — Conflict resolver UI

## Behavior
- Opens over the graph area from the banner (Resolve Next), Repository ▸ Resolve Conflicts, the working
  directory's Conflicts section, or automatically when an operation stops with conflicts.
- Panes: OURS | (BASE) | THEIRS above, RESULT below — opaque `CodeLinesView`s (virtualized, syntax per visible
  row), conflict rows tinted `conflict.bg`, resolved rows `resolved.bg`, the current block selected and
  scroll-synced in every pane. Labels per operation (ADR-0033); rebase shows a one-time explanation strip.
- Chrome: one floating glass control group — block navigator (⌥⌘↑/⌥⌘↓), Show Base, Save (⌘S), Mark as
  Resolved (⇧⌘R, `.glassProminent` once every block is resolved), Close (Esc).
- Block actions (plain opaque buttons above the result): Take Ours, Take Theirs, Both (ours→theirs,
  theirs→ours, base), Edit… (plain-text editor sheet, no smart quotes), Reset; ⌘Z / ⇧⌘Z undo/redo.
- Save writes `render(choices)` atomically behind the hash guard; Mark as Resolved saves if needed, asks when
  marker-like lines remain, then `git add`. A changed file on disk shows "changed outside Jit" with Reload from
  Disk / Keep My Result; saving is blocked until the user chooses.
- When no conflicts remain: "All conflicts are resolved" with Continue.

## Deviation
- Per-block actions are a strip above the result pane, not buttons inline in each block (same actions, plain
  controls, one place); manual edits use a sheet editor rather than editing the result pane in place.

## Tests / verification
Model logic covered by `ConflictTests` (render, save, mark) and the pointer pass: merge with 3 blocks (ours,
theirs, hand edit) → staged result verified byte-for-byte → Continue → merge commit by the profile; rebase
labels; stash-pop conflict; dark mode screenshots.
